# Testing and Acceptance Checklist

Mark each item `PASS`, `FAIL`, or `NOT RUN`; include notes and evidence in phase reports.

## Project setup
- [ ] Dependencies install successfully.
- [ ] Astro dev server starts.
- [ ] Production build succeeds.
- [ ] Type checking/linting succeeds if configured.
- [ ] README commands match actual project scripts.

## Required content
- [ ] Hero headline exactly matches `Hi, I'm Suyash Anil Borse.`
- [ ] Sub-headline contains `Java Developer | Web Engineer | Algorithmic Problem Solver`.
- [ ] CTA labels are exactly `View Projects` and `Contact Me`.
- [ ] About identifies a 2nd-year B.Tech Information Technology student at R. C. Patel Institute of Technology.
- [ ] About mentions daily CodeChef and LeetCode practice and passion for Data Structures & Algorithms.
- [ ] Languages include Java, JavaScript, TypeScript, SQL.
- [ ] Frontend includes React, Tailwind CSS, Next.js.
- [ ] Backend/Data includes Node.js, Supabase, Firebase, MySQL, MongoDB.
- [ ] Tools include Git, GitHub, VS Code, Power BI.
- [ ] EcoPilot AI exists with an editable description placeholder.
- [ ] KanFlow description exactly includes `A comprehensive Kanban board system.`
- [ ] SIH 2026 Submissions description/context matches the specified architecture blueprint scope.
- [ ] All project cards provide tech-stack pills and GitHub/Live Demo affordances without fabricated links.
- [ ] Footer/social area includes GitHub, LinkedIn, CodeChef, LeetCode or clearly labelled unconfigured placeholders.
- [ ] Contact form is EmailJS-ready and accurately reports its configuration/submission state.

## Responsive and visual
- [ ] Narrow mobile viewport: no horizontal overflow.
- [ ] Tablet layout is balanced.
- [ ] Desktop layout has appropriate max width and spacing.
- [ ] Typography is readable and hierarchy is clear.
- [ ] Indigo/cyan accents are used consistently and sparingly.
- [ ] Navigation remains usable at all supported widths.
- [ ] Interactive cards have visible focus states as well as hover states.

## Accessibility
- [ ] Skip link works.
- [ ] Semantic landmarks are present.
- [ ] Heading order is logical.
- [ ] All controls are keyboard reachable.
- [ ] Focus is visible.
- [ ] Form fields have labels and useful errors.
- [ ] Status updates are announced accessibly.
- [ ] Reduced-motion preference is respected.
- [ ] Animated headline remains understandable without animation.
- [ ] Color contrast is reviewed.

## Functionality and resilience
- [ ] Navigation anchors target existing sections.
- [ ] Outbound links only use configured, valid destinations.
- [ ] No dead `#` links.
- [ ] Missing EmailJS configuration produces a clear setup-needed state.
- [ ] Invalid form data is rejected.
- [ ] Success appears only after confirmed provider success.
- [ ] Provider failure is handled honestly.
- [ ] Duplicate submissions are prevented or guarded.
- [ ] No credentials or private keys are committed.

## SEO and performance
- [ ] Title and description are present.
- [ ] Open Graph metadata is present with placeholder/configured asset handling.
- [ ] Canonical URL is not fabricated.
- [ ] Favicon is present.
- [ ] Build output is checked.
- [ ] Client hydration is limited to interactive components.
- [ ] No avoidable console errors or hydration warnings.

## Final handoff
- [ ] README has install, dev, build, preview, configuration, and deployment instructions.
- [ ] `.env.example` contains placeholders only.
- [ ] All five phase reports exist.
- [ ] Unresolved owner inputs are listed clearly.
- [ ] No public deployment occurred without owner authorization.
